# Scramble Ritual — 실시간 인터랙션 설치 설계

〈Scramble Ritual: 135ms to 319ms〉를 데모가 아닌 **전시장에서 무인으로 도는 실시간 악기**로
만들기 위한 시스템 설계. (아트코리아랩 2026, 3~12월)

## 0. 설계 원칙

1. **지연 135ms 미만** — 작품 제목의 하한이 곧 기술 예산. 손이 오브제를 움직인 순간부터
   소리가 변하기까지 135ms를 넘지 않는다 (넘으면 "반응"이 아니라 "재생"으로 느껴짐).
2. **오브제가 곧 소리** — 어떤 웨이브폼을 집어도 *그* 조각이 울려야 한다. 등장 순서가 아니라
   물리적 정체성(형상)이 소리를 결정한다.
3. **무인 8시간** — 전시는 아무도 지키지 않는다. 자동 시작·자동 복구·우아한 실패.
4. **관람자는 설명서를 읽지 않는다** — 놓으면 소리가 나고, 움직이면 변하고, 떠나면
   작품이 스스로 숨쉰다. 상태 전환은 전부 자동.

## 1. 시스템 구성

```
[라이트박스(하부 발광)] ← 16개 아크릴 웨이브폼 오브제
        ↑ 수직 부감 카메라 (노출 고정, 30~60fps)
        │
┌───────┴────────────────────────── Mac mini (무인 운영) ──┐
│ tracker (Python)                                          │
│   vision: 실루엣 검출(invert+Otsu) → 형상 매칭(정체성)      │
│   scene:  ID 추적·접촉·겹침 → 특징(disorder/scatter/…)     │
│   state:  IDLE ↔ ACTIVE 상태기계                          │
│   sound:  SoundMapper → OSC                               │
│   watchdog: fps·카메라·오디오 감시, 자동 재시작              │
└───────┬───────────────────────────────────────────────────┘
        │ OSC (/scramble/…, 기존 명세 그대로)
        ▼
[Max/MSP] 그래뉼러 8ch ──→ 스피커 8기 (전시) / 스테레오 (개발)
[conductor → 144ch 릴레이] (후속: 빛·키네틱 응답, OSC 훅만 예약)
```

내장 그래뉼러 신스는 **개발·리허설·Max 다운 시 폴백**으로 유지 — 전시 본선은 Max/MSP.

## 2. 지연시간 예산 (목표 총합 < 135ms)

| 구간 | 예산 | 방법 |
|---|---|---|
| 카메라 노출+전송 | 17~33ms | 60fps 카메라면 17ms. 노출 고정 필수(자동노출 = 지연+흔들림) |
| 검출+형상매칭 | ≤10ms | 720p 실루엣은 가벼움. 형상매칭은 후보만(신규/불확실 트랙) |
| 추적 EMA | ~1프레임 | pos_alpha 0.55 유지, 급변 시 스냅(큰 이동은 스무딩 건너뜀) |
| OSC 전송 | <1ms | 로컬 UDP |
| 오디오 버퍼 | ~11ms | 512 샘플 @48k. Max도 I/O vector 동일 수준 |
| **합계** | **약 50~70ms** | 여유분은 프레임 드랍 대비 |

측정 도구: 브링업에 `--latency` 모드 추가 예정 — 화면 플래시→마이크 캡처로 실측.

## 3. 오브제 정체성 — 형상 매칭 (핵심 신규 설계)

**문제**: 현 Arranger는 등장 순서로 조각을 배정 → 오브제를 치웠다 다시 놓으면 다른 소리가 남.
작품 문법("이 웨이브폼 = 이 소리")이 깨진다.

**해법**: 실루엣 형상으로 오브제를 식별한다. 웨이브폼 16개는 서로 다른 포락선 실루엣이므로
형상 자체가 ID다. 백라이트의 깨끗한 컨투어가 이걸 가능하게 한다.

- **등록(1회)**: 캘리브레이션 때 오브제를 하나씩 올려 기준 컨투어 16개 저장
  (`shapes/`) — 또는 제작 원본 SVG에서 생성.
- **런타임**: 신규/불확실 검출만 기준 형상과 대조(cv2.matchShapes 또는 회전불변 서명),
  헝가리안 배정 + 히스테리시스(연속 N프레임 일치 시 확정). 확정된 트랙은 재대조 안 함.
- **부수 효과 — 손 문제 해결**: 손·팔 실루엣은 어떤 기준 형상과도 안 맞음 → 자동 무시.
  max_objects 같은 강제 컷이 필요 없어짐.
- **폴백**: 매칭 신뢰도가 낮으면(마모·부분 가림) 기존 스프레드 순서 배정으로 강등.

## 4. 인터랙션 상태기계 (관람 드라마투르기)

```
IDLE ──(오브제 이동 감지)──▶ ACTIVE ──(90초 정지)──▶ IDLE
```

- **ACTIVE**: 현 매핑 그대로 — 배치=편곡, 자세=해체. 즉각 반응.
- **IDLE(숨쉬기)**: 관람자가 없을 때. 마지막 배치의 소리를 낮은 음량으로 유지하되
  파라미터에 느린 LFO(수 분 주기)를 얹어 "작품이 혼자 숨쉬는" 상태.
  **기억 재생**: recorder 로그에서 지난 관람자들의 배치 시퀀스를 낮게 리플레이
  — 의식(ritual)의 잔향. 기존 recorder/replay 인프라 재사용, 신규 비용 거의 없음.
- 전환은 2~3초 크로스페이드 (급격한 음량 변화 금지).
- 이동 감지 = 트랙 위치 변화량 합 > 임계값 (이미 추적 중인 값, 추가 센서 불필요).

## 5. 음악 체계 — 제목의 숫자를 시간 구조로

1. **모핑 펄스 그리드**: 그레인 스폰을 펄스에 퀀타이즈하되, 펄스 간격 자체가
   scramble을 따라 **319ms(정렬) ↔ 135ms(해체)** 사이를 모핑. 제목의 두 숫자가
   입자 길이(현행)이자 시간 그리드(신규)가 됨. 정렬=장중한 맥동, 해체=조급한 세분.
2. **음고 용해**: pitch_scatter를 연속값 대신 단계적 스케일로 —
   정렬: 유니즌 → 약간 흐트러짐: 펜타토닉 → 더: 크로매틱 → 해체: 미분음 디튠.
   기울임이 "화성이 탁해지는" 과정으로 들림.
3. **거시 형식**: 상태기계가 섹션을 만든다 (IDLE=서주/잔향, ACTIVE=본론).
   추가 규칙: scramble > 0.85가 60초 지속되면 완만한 침묵으로 붕괴 후 재생(reset) —
   해체의 끝을 작품이 선언.

구현 위치: 내장 신스와 Max 패치 양쪽에 동일 규칙 (OSC로 pulse_ms, scale 인덱스 추가 송출).

## 6. 캘리브레이션 & 운영 (전시 신뢰성)

**설치 시 1회 (목표 15분)**:
1. 카메라 수평·프레이밍 → `--calibrate`: 빈 라이트박스 캡처(배경 기준), 노출·WB 잠금,
   ROI(발광 영역) 자동 검출
2. 오브제 16개 순차 등록(형상 ID) — 하나 올리고 키 한 번, 반복
3. venue 프로파일 저장 (`config/venue-<이름>.json`) — 장소별 조명·카메라 차이 흡수

**무인 운영**:
- launchd 자동 시작 (전원 인가 → 3분 내 소리)
- watchdog: fps < 20 지속, 카메라 소실, OSC 무응답 → 해당 프로세스만 재시작 (소리는
  페이드아웃 후 재개, 뚝 끊김 금지)
- Max 다운 → 내장 신스 자동 인계 (OSC 송신은 계속, 복구 시 페이드 교대)
- 로그: 일자별 JSONL (관람 통계·기억 재생 소스 겸용), 7일 로테이션
- 전시 시간표: cron으로 개장 페이드인 / 폐장 페이드아웃

## 7. 확장 훅 (설계만 예약, 지금 구현 안 함)

- **8ch 공간화**: /scramble/obj 의 정규화 좌표 → Max에서 8각 패닝. 명세 변경 불필요.
- **144ch 릴레이(conductor)**: OSC /scramble/param/* 를 conductor 엔진이 구독 →
  scramble 값이 빛/키네틱 패턴 밀도로. 시뮬레이션 검증 완료 상태라 배선만 남음.
- **다인 동시 조작**: 형상 ID 덕에 자연 지원 (누가 만지든 오브제=소리 불변).

## 8. 로드맵 (라이트박스 도착 기준)

| 단계 | 내용 | 전제 |
|---|---|---|
| M1 | 라이트박스 브링업: --backlight 실검증, 노출 잠금, --calibrate | 라이트박스 |
| M2 | **형상 ID**: 등록 도구 + 매칭 + 손 무시 (합성 씬으로 선행 개발 가능) | 없음(지금 가능) |
| M3 | 상태기계 + 기억 재생 (sandbox로 선행 개발 가능) | 없음(지금 가능) |
| M4 | 음악 체계: 모핑 펄스 + 음고 용해 (내장 신스 먼저) | 없음(지금 가능) |
| M5 | Max/MSP 본 패치 (스테레오 → 8ch), 실음원 4종 확정 | 사운드 소스 |
| M6 | 운영 하드닝: watchdog·자동시작·venue 프로파일·실측 지연 | 전시 리허설 |
| M7 | 릴레이 통합 (선택) | 릴레이 하드웨어 |

M2·M3·M4는 라이트박스 없이 합성 씬/샌드박스로 지금 개발·검증 가능 — 하드웨어 대기와
소프트웨어 개발이 병렬로 간다.
