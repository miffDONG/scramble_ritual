# OSC 전송 값 정의

웹 튜너 → 외부 사운드(Max/MSP · TouchDesigner)로 보내는 값의 정의.

전송되는 메시지는 **한 가지뿐**이다:

| 계열 | 주소 | 내용 |
| --- | --- | --- |
| ① 개별 오브제 | `/scramble/obj` | 오브제 하나의 위치·기울기·**긴장도**·상태 |

`tension`은 예전엔 쌍(`/pair`)으로 보냈으나, 지금은 기본 MST에서
**각 오브제에 직접 연결된 간선으로 계산한 값 하나**를 `/obj`에 실어 보낸다.

- **송신 조건**: 웹 UI에서 OSC 송신을 켰을 때만. 대상 호스트/포트/프리픽스는 UI에서 지정(프리픽스 기본 `/scramble`).
- **주기**: 매 프레임(파이프라인 fps와 동일, 보통 20~25fps). 실제 송신 속도는 웹 헤더의 `OSC …fps` 배지에서 확인.
- **메시지 수**: 오브제 N개일 때 한 사이클에 `N` 개(O(n), 쌍 수와 무관).
- **오브제 식별자**: **모스 이진값**(`bits`). 위치 순번이 아니라 오브제 고유의 값이므로, 오브제가 서로 지나가도 바뀌지 않는다.

---

## ① 개별 오브제 — `/scramble/obj`

오브제 1개당 1메시지.

| # | value name | 타입 | 범위 | 측정 기준 | 의미 |
| --- | --- | --- | --- | --- | --- |
| 0 | `bits` | string | `"01100001"` | 모스 체인(시작 마커 뒤 8심볼)을 판독한 값. 점=`0`, 선=`1` | **오브제 식별자.** 어떤 오브제인지 = 어떤 사운드 소스인지 |
| 1 | `x` | float | 0.0 ~ 1.0 | 오브제 판 중심의 x를 **기준 영역**(아래 참고) 폭으로 정규화 | 개별 오브제의 가로 위치. 좌=0, 우=1 → 패닝에 대응 |
| 2 | `y` | float | 0.0 ~ 1.0 | 오브제 판 중심의 y를 **기준 영역** 높이로 정규화 | 개별 오브제의 세로 위치. 상=0, 하=1 |
| 3 | `tilt` | float | −180.0 ~ +180.0 | 모스 읽기축(시작 마커 → 심볼) 방향을 이미지 좌표에서 잰 각도(도) | **그 오브제 자체의 기울기.** 다른 오브제와의 차이가 아님 |
| 4 | `tension` | float | 0.0 ~ 1.0 | 기본 MST의 incident edge에서 계산(아래 그래프·fold) | **그 오브제에 걸리는 긴장도.** 가까운 오브제가 있을수록 큼 |
| 5 | `flip` | int | 0 또는 1 | 현재는 UI에서 사람이 지정하는 플래그(자동 판별 아님) | 뒤집힘 상태. `1`이면 **역재생** |
| 6 | `freq` | float | −12.0 ~ +12.0 | 오브제별 피치 지정값. 미지정이면 ID에서 파생한 밴드 | **오브제별 주파수**(세미톤). 오브제를 음역으로 분리 |

### 각도(`tilt`) 규약 — 주의
이미지 좌표계라 **+y가 아래**다. 따라서 **화면상 시계방향이 +**:

| 체인이 향하는 방향 | `tilt` |
| --- | --- |
| 오른쪽 → | `0°` |
| 아래 ↓ | `+90°` |
| 위 ↑ | `−90°` |
| 왼쪽 ← | `±180°` |

수학 관례(반시계가 +)와 **부호가 반대**이므로, 회전에 매핑할 땐 필요 시 부호를 뒤집을 것.
값은 항상 −180~+180으로 감긴다(자동 회전으로도 무한히 커지지 않음).

### 기준 영역 — 테이블(ROI)이 단위가 된다

| 상태 | 기준 영역 |
| --- | --- |
| **테이블 영역(ROI) 지정됨** | **ROI 사각형** — 원점=ROI 좌상단, `x`=ROI 폭·`y`=ROI 높이로 정규화 |
| ROI 없음 | 처리 프레임 전체 (축소 후 크기) |

**ROI를 잡으면 테이블이 단위 사각형이 된다.** `x=0`은 테이블 왼쪽 끝,
`x=1`은 오른쪽 끝. 그래서 **카메라를 옮기거나 줌·해상도를 바꿔도 같은 물리
배치는 같은 값**이 나온다 — 전시에서 카메라를 재설치해도 사운드 매핑이 유지된다.
현장에서는 반드시 테이블 영역을 지정할 것.

`x`는 폭, `y`는 높이로 각각 정규화하므로 기준 영역이 정사각형이 아니면
`x`와 `y`의 1.0이 같은 물리 거리는 아니다. tension 계산의 거리는 이와 별개로
**테이블 긴 변**으로 정규화한다(아래).

## 긴장도(`tension`) 정의

각 오브제 `i`의 tension은 두 단계로 계산된다: **쌍 거리 곡선** → **fold**.

### 1) 쌍 거리 곡선 `pair_tension`

두 오브제 중심거리를 **테이블 긴 변**으로 정규화한 `dist`에 대해:

```
if dist >= d_far:  0
if dist <= d_near: 1
else:              (d_far − dist) / (d_far − d_near)   # 선형 상승
```

| 상태 | `dist` | tension |
| --- | --- | --- |
| 멀리 떨어짐 | ≥ `d_far` | `0.0` |
| 가까워지는 중 | `d_far` → `d_near` | `0.0` → `1.0` 상승 |
| **변이 닿음·겹침** | ≤ `d_near` | **`1.0` (유지)** |

- `d_near` (tension=1 시작) = 정삼각형 두 개가 변끼리 맞닿는 중심거리 =
  `한 변 / √3`, 테이블 긴 변으로 정규화. 한 변 길이는 `object_side_px`
  (objects 소스는 시뮬 값 자동, 그 외는 "한 변 측정" 드래그값; 미지정 시
  `tension_contact` 폴백).
- `d_far` (tension=0 기점) = **테이블 긴 변의 절반 = `0.5`(고정)**.
  정사각 크롭이면 한 변의 절반, 직사각이면 긴 변의 절반에서 0이 된다.
- **겹쳐도 0으로 치환하지 않는다**(예전 곡선의 접촉 후 하강 로직 제거) — 단조.

### 2) 그래프 연결과 노드별 fold

기본값인 MST는 모든 오브제를 거리 가중치로 연결한 뒤 전체에서 정확히 `n−1`개
간선만 남긴다. 오브제 `i`의 tension은 전체 `n−1`개를 한꺼번에 접는 값이 아니라,
**MST에서 `i`에 직접 닿은 간선들의 `pair_tension`만** 하나로 접은 값이다.
두 규칙 모두 **런타임 옵션**이라 UI(OSC 송신 패널)에서 바꿔 무대에서 비교할 수 있다.

| 옵션 | 값 | 의미 |
| --- | --- | --- |
| `tension_connect` | `mst`(기본) | 거리 합이 최소인 신장 트리. 전체 n−1개 간선, 노드별로는 직접 연결된 간선만 사용 |
| | `all` | 본인 제외 n−1개 전부 |
| | `near` | **`tension_link_radius` 이내만** 연결(먼 링크 제외) |
| | `knn` | 가장 가까운 `tension_knn`개(기본 3) |
| `tension_link_radius` | `0.2`(기본) | `near`의 연결 반경(긴 변 정규화). `d_far`(0.5)와 **분리**돼 있어, 작게 둘수록 `near`가 `all`과 실제로 달라진다 |
| `tension_fold` | `max`(기본) | 가장 팽팽한 쌍이 대표. n 무관 0~1 풀레인지 |
| | `avg` | 평균. 부드럽지만 먼 오브제(0)로 희석될 수 있음 |
| | `min` | 가장 느슨한 쌍 |

> **주의 — `max` fold에서는 연결 방식의 차이가 tension 값에 거의 드러나지 않는다.**
> MST도 각 노드의 최근접 간선을 포함하므로 `all`·`knn`과 같은 최댓값을 내는 것이
> 일반적이다(`near`가 최근접 간선까지 제외하면 예외). 연결 방식의 차이는
> **`fold=avg` 또는 `min`** 에서 가장 잘 드러난다.
> 또한 `near`의 반경이 `d_far`(0.5=긴 변 절반)와 같으면 일반적인 테이블 배치에선
> 모든 쌍이 그 안에 들어와 `near == all`이 된다. 그래서 `tension_link_radius`를
> 그보다 작게(예: 0.2) 두어야 `near`가 실제로 먼 링크를 잘라낸다.

## 전송 예시 (오브제 3개, connect=mst·fold=max)

```
/scramble/obj    10001110  0.30  0.40   30.0  0.66  0  -5
/scramble/obj    01001101  0.62  0.55  -45.0  0.80  1   4
/scramble/obj    11100100  0.80  0.30    0.0  0.42  0  -4
```

읽는 법: 필드 순서는 `bits, x, y, tilt, tension, flip, freq`. 두 번째
오브제(`01001101`)는 `flip=1`이라 역재생, 주파수 `+4` 세미톤, 가장 가까운
이웃이 있어 tension이 가장 높다(`0.80`).

## 수신 측 권장 사항

1. **보이스는 `bits`로 물릴 것.** 이 값이 오브제의 정체성이다. 오브제가 화면에서 서로 지나가도 바뀌지 않는다.
2. **오브제가 사라지면** 해당 `bits`의 `/obj`가 더 이상 오지 않는다. 일정 시간(예: 0.5초) 수신이 없으면 그 보이스를 페이드아웃할 것.
3. **보간**: 매 프레임 갱신되지만 20~25fps라 계단이 보일 수 있다. 수신 측에서 50ms 내외 라인 보간 권장.
4. 같은 `bits`를 가진 오브제를 둘 이상 두면 구분되지 않는다. 시뮬에서 ID를 서로 다르게 줄 것.

## 보내지 않는 값

**개별 오브제(`/obj`)만** 전송한다. 다음은 보내지 않는다:
오브제 조합(`/pair`)·쌍 거리(`dist`), 씬 오브제 수(`/count`), 씬 종합 긴장도(`/tension`),
사운드 파라미터(`/param/*`), 접촉·해제·뒤집힘 이벤트(`/event/*`), 각도 차이(상대 기울기).

접촉 순간이 필요하면 수신 측에서 오브제 `tension`이 임계값(예: 0.95)을 넘는 순간으로 판단할 것.
