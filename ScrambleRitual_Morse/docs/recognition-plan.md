# Morse 인식 강화 계획 (현장 테스트 대비)

날짜: 2026-07-18 · 현장 테스트: 2026-07-20 (백라이트 패널, 흰색 각인 판)

## 현장 조건 정리

- 조명: 위에서 아래가 아니라 **아래에서 위로 빛을 쏘는 백라이트 패널**
  (흰색 배경). 배경이 매우 밝고(≈180 이상), 손이 화면에 들어오면 짙은
  실루엣이 히스토그램의 어두운 꼬리를 지배한다.
- 마크: 검은 펜이 아니라 **흰색 각인**. 각인은 빛을 산란시키므로 카메라
  각도에 따라 배경보다 *밝게* 보일 수도, 투과광을 가려 *어둡게* 보일
  수도 있다 → 극성을 현장에서 골라야 한다.
- 오브제: `sampleVideo/morse-26.07.20 update.png` 시안. 시작 마커가
  ■ 외에 ★, ▲ 변형으로 확장, 데이터 심볼은 점/선 8개로 동일.

## 근거 (이미 확인한 것)

`../sampleVideo/morseCode.MOV`가 실제 라이트박스 위 촬영본이다. 분석 결과:

- 기본 세팅(전역 percentile, clamp [40,120])은 **0 프레임 인식**.
  원인: 손 실루엣이 어두운 꼬리를 차지해 임계값이 41로 내려가고,
  마크(밝기 ≈120–160)가 전부 통과된다.
- `threshold_mode=adaptive`(국소 평균 대비)로 바꾸면 같은 프레임에서
  체인 심볼 8/8이 분리된다. → 현장 프리셋은 adaptive 기반으로 구성.
- 단, 이 영상 속 판은 **시작 마커(앵커)가 없는 구형 시안**이다. 마크
  열이 ■/★/▲ 없이 점·선 8개로만 되어 있어, 앵커에 의존하는 기본
  경로(`require_start=True`)로는 카드가 하나도 안 잡힌다. → 아래
  "무앵커 모드" 참고. 신형 오브제(2026-07-20 시안)는 시작 마커가
  있으므로 실물 경로는 `require_start=True`를 쓴다.

## 무앵커 모드 (require_start=False) — 마크 판독 우선 테스트

테스트 첫 단계 목표는 ID 매칭보다 **마크 8개 자체를 안정적으로 읽는
것**이다. 시작 마커를 찾는 과정을 옵션으로 분리했다:

- `require_start=True`(기본): 시작 마커를 찾고 그 뒤 8심볼 체인을 읽는다
  (실물 오브제 경로).
- `require_start=False`: 앵커 없이 화면의 블롭 중 **일직선으로 늘어선 8개**
  를 찾아 읽는다(`_best_chain_anchorless`). 읽기 방향은 관례로 고정
  (세로 카드는 위→아래), 코드북 매칭 시 역방향도 시도한다.

검증:
- 합성(시작 마커 없이 렌더한 8마크): 0/30/90° 전부 정확히 판독
  (`tests/test_morse.py::test_anchorless_reads_chain_without_start_marker`).
- morseCode.MOV(백라이트 구형 시안, 작은 마크 + 파형 각인 노이즈):
  관대한 체인 게이트(gap 3.5, perp 2.0) + adaptive로 약 45% 프레임에서
  8블롭 체인 검출. 시간축 투표(`stabilize`)와 합쳐 안정화. 이 영상은
  마크가 작고 흐려 프레임별 편차가 크므로, 실물 오브제(더 크고 선명 +
  시작 마커)에서는 `require_start=True`가 더 안정적이다.
- 웹 UI 상황 축에서 **앵커=무앵커 + 마크 감도=작은/흐린 + 체인 관용도=관대**
  조합으로 적용.

## 적용 완료 (테스트 방법 포함)

1. **극성 전환** — `dark_on_light` 끄면 밝은 마크 판독.
   percentile 꼬리 방향·대비 게이트 부호가 함께 뒤집힌다.
   테스트: `tests/test_morse.py::test_bright_marks_on_dark_background`,
   웹 UI의 **시뮬(백라이트)** 소스.
2. **국소(adaptive) 이진화 파라미터화** — `adaptive_block_px`,
   `adaptive_c` 옵션 추가. 백라이트+손 상황에서 전역 임계값의 실패를
   회피. 테스트: 웹 UI에서 `--video ..\sampleVideo\morseCode.MOV` 재생
   후 현장 프리셋 적용, 마스크 탭에서 심볼 8개 분리 확인.
3. **조명 평탄화** — `normalize_illumination`: 배경 조도로 나눠 패널
   밝기 불균일 제거. 테스트:
   `tests/test_morse.py::test_normalize_illumination_recovers_uneven_backlight`
   (좌우 0.35→1.0 조도 램프에서도 정상 디코드).
4. **★/▲ 앵커 대응** — `square_max_vertices` 옵션화(★는 12),
   `square_min_extent` 완화 가이드(0.35), 합성 렌더러에 `marker_shape`
   추가. 테스트: `tests/test_morse.py::test_triangle_and_star_anchors`.
5. **시간축 안정화(비트 투표)** — `tracker/stability.py`. 카드를 중심
   좌표로 추적하며 슬롯별 다수결 투표. 한 프레임 오독(모션 블러, 손
   가림, 백라이트 플리커)이 ID를 흔들지 못한다. 웹 UI "안정화 ID"
   표가 이 결과. 테스트: `tests/test_stability.py` 6케이스
   (글리치 억제, 트랙 유지, 드롭아웃, 교체 반응).
6. **웹 실시간 튜닝** — 모든 옵션이 조작 즉시 프레임에 반영되므로
   현장에서 몇 분 안에 세팅을 맞출 수 있다 (`docs/options.md`).

## 현장에서 추가로 시도할 것 (우선순위순)

1. **카메라 노출 고정**: 자동 노출이 손 출입마다 배경 밝기를 바꾼다.
   카메라 드라이버에서 노출/화이트밸런스를 수동 고정하면 adaptive가
   아니어도 fixed 임계값이 안정적으로 동작한다.
2. **판별 각도 확보**: 각인 마크는 카메라와 패널이 정면일 때 대비가
   최저가 된다. 카메라를 패널 법선에서 10~20° 기울이면 산란광 때문에
   각인이 확실히 밝아진다 — 현장에서 가장 효과가 클 물리적 개선.
3. **`slots` 재확인**: 26.07.20 시안 기준 8이 맞는지 실물 도착 시 확인.
4. **테이블 영역(ROI)** — 구현됨. 웹 뷰에서 드래그로 사각형을 지정하면
   그 안에서만 추론한다. 영역 밖은 배경 극성으로 채워져 글리프를 만들지
   않고 임계값 히스토그램도 오염시키지 않는다(백라이트에서 손이 프레임에
   들어와도 ROI 밖이면 무시). 결과는 ROI 안으로 한 번 더 필터. 정규화
   좌표로 저장되어 해상도 무관, config 프로파일에 포함. 서버:
   `roi_to_px`/`set_roi`/`/api/roi` (webui/server.py).
5. 남는 개선 아이디어(필요 시): 앵커 모양(■/★/▲)을 ID 네임스페이스로
   사용해 코드 공간 3배 확장, 퍼스펙티브 보정(패널 4모서리 클릭) 후
   검출(현재 ROI는 사각형; 기울어진 판은 사각형으로 넉넉히 감싸면 됨).

## 현장 튜닝 절차 (요약)

1. `scripts\start.bat --camera 0` 실행 → 브라우저 자동 오픈.
2. 판을 패널에 올리고 **마스크 탭**으로 전환.
3. **조명 축**을 상부/백라이트로, **각인 색상 축**을 검정/하양으로
   번갈아 → 마크가 하얗게 분리되는 조합 선택.
4. `adaptive_c` ↓ = 흐린 각인까지, ↑ = 노이즈 제거. 심볼 9개(앵커+8)가
   전부 나올 때까지 조정 (또는 **마크 감도 축**을 작은/흐린 마크로).
5. 오버레이 탭에서 체인 라인·비트 확인, "안정화 ID"가 고정되는지 확인.
6. **[config.json 저장]** → 이후 CLI/공연 실행에도 같은 세팅 적용.
