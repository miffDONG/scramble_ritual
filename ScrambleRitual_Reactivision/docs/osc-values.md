# OSC 전송 값 정의

전시 서버(`webui/exhibit_server.py`) → SuperCollider · TouchDesigner.

전송되는 메시지는 **한 가지뿐**이다:

| 주소 | 내용 |
| --- | --- |
| `/scramble/obj` | 오브제 하나의 식별자·위치·기울기·**긴장도** |

- **송신 조건**: 웹 UI에서 OSC 송신을 켰을 때. 대상은 목록(기본 SuperCollider 127.0.0.1:57120, TouchDesigner 127.0.0.1:7000)이며
  모든 대상이 **같은 값**을 받는다. 형식은 **기본 json**(인자 1개 = JSON 문자열)이며 대상마다 list / dict로 바꿀 수 있다. 프리픽스 기본 `/scramble`.
- **주기**: 카메라 프레임마다(reacTIVision의 TUIO fseq마다, 예: 120fps 설정·노출 1/64s면 약 64fps). 헤더의 `OSC …fps` 배지가 실측.
- **메시지 수**: 오브제 N개 → 사이클당 대상별 N개.
- **오브제 식별자**: reacTIVision **피듀셜 심볼 번호**(`id`, int). 위치 순번이 아니라 마커 고유 번호이므로 오브제가 서로 지나가도 바뀌지 않는다.

## `/scramble/obj` — 오브제 1개당 1메시지

| # | value name | 타입 | 범위 | 측정 기준 | 의미 |
| --- | --- | --- | --- | --- | --- |
| 0 | `id` | int | 0 ~ 215 (amoeba 기본 세트) | reacTIVision 피듀셜 심볼 번호 | **오브제 식별자** = 어떤 사운드/영상 소스인지 |
| 1 | `binary_id` | string | `"00000000"` ~ `"11010111"` | `id`를 8비트 0패딩 이진 문자열로 | 같은 식별자의 이진 표기(이전 Morse `bits` 자리). `int(binary_id, 2) == id` |
| 2 | `x` | float | 0.0 ~ 1.0 | 마커 중심 x를 **기준 영역** 폭으로 정규화 | 가로 위치. 좌=0, 우=1 |
| 3 | `y` | float | 0.0 ~ 1.0 | 마커 중심 y를 기준 영역 높이로 정규화 | 세로 위치. 상=0, 하=1 |
| 4 | `tilt` | float | −180.0 ~ +180.0 | reacTIVision 각도를 도 단위로 wrap | **그 오브제의 기울기.** `rtv_angle_offset`으로 0° 기준 보정 가능 |
| 5 | `tension` | float | 0.0 ~ 1.0 | 연결 그래프(기본 MST) 이웃과의 거리에서 계산 | **그 오브제에 걸리는 긴장도.** 가까운 이웃이 있을수록 큼 |
| 6 | `flip` | int | 0 | reacTIVision은 뒤집힘을 검출하지 않음 | 항상 0 (자리 유지) |
| 7 | `freq` | float | −6 ~ +5 | `((id × 5) mod 12) − 6` | 오브제별 세미톤 밴드(ID에서 파생) |

형식별 표현:
- `list`: `[id, binary_id, x, y, tilt, tension, flip, freq]` (위 순서)
- `dict`: `["id", id, "binary_id", binary_id, "x", x, …]` (키·값 번갈아)
- `json`: 인자 1개 = `{"id": …, "binary_id": "…", "x": …, …}` JSON 문자열

### 각도(`tilt`) 규약
이미지 좌표(+y 아래)라 **화면 시계방향이 +**. 오른쪽 0°, 아래 +90°, 위 −90°, 왼쪽 ±180°. TUIO 각도(0~2π)를 그대로 wrap한 값이라
마커의 "위" 방향 기준은 reacTIVision 심볼 규약을 따른다. 사운드/영상 쪽 0° 기준이 다르면 `rtv_angle_offset`(도)로 맞춘다.

### 기준 영역 — 테이블(ROI)
| 상태 | 기준 영역 |
| --- | --- |
| 테이블 영역(ROI) 지정됨 | ROI 사각형 — 원점=ROI 좌상단, `x`=ROI 폭·`y`=ROI 높이로 정규화 |
| ROI 없음 | 카메라 프레임 전체 |

ROI를 잡으면 테이블이 단위 사각형이 되어, 카메라를 옮기거나 해상도를 바꿔도 같은 물리 배치는 같은 값이 나온다.
`x`는 폭, `y`는 높이로 각각 정규화하므로 정사각이 아니면 `x`·`y`의 1.0이 같은 물리 거리는 아니다.
긴장도 계산의 거리는 이와 별개로 **테이블 긴 변**으로 정규화한다.

## 긴장도(`tension`) 정의

각 오브제 `i`의 tension은 **연결 그래프** → **쌍 거리 곡선** → **fold** 순으로 계산된다.

### 1) 연결 그래프 `tension_connect`
| 값 | 의미 |
| --- | --- |
| `mst` (**기본**) | 오브제 중심거리로 **최소 신장 트리**(Kruskal)를 만든다. n개 오브제가 n−1개 간선으로 하나의 나무가 되고, 각 오브제는 **트리 이웃**만 본다. 배치가 하나의 사슬/가지 구조로 읽히며, 오버레이의 연결선이 곧 이 트리다 |
| `all` | 본인 제외 n−1개 전부 |
| `near` | `tension_link_radius`(기본 0.2, 긴 변 정규화) 이내만 |
| `knn` | 가장 가까운 `tension_knn`개(기본 3) |

### 2) 쌍 거리 곡선 `pair_tension`
두 오브제 중심거리를 테이블 긴 변으로 정규화한 `dist`에 대해:
```
if dist >= d_far:  0
if dist <= d_near: 1
else:              (d_far − dist) / (d_far − d_near)   # 선형 상승
```
- `d_near`(tension=1 시작) = 정삼각형 두 개가 변끼리 맞닿는 중심거리 = `한 변 / √3` (한 변은 UI의 "한 변 측정" 값, 미지정 시 `tension_contact` 폴백).
- `d_far`(tension=0 기점) = 테이블 긴 변의 절반 = `0.5` 고정. 겹쳐도 1을 유지한다(단조).

### 3) fold `tension_fold`
| 값 | 의미 |
| --- | --- |
| `max` (기본) | 가장 팽팽한 연결이 대표. 항상 0~1 풀레인지 |
| `avg` | 연결된 이웃 평균. 그래프 방식(mst/all/near/knn)의 차이가 여기서 드러난다 |
| `min` | 가장 느슨한 연결 |

> `max` fold에서는 가장 가까운 이웃이 항상 MST에도 포함되므로 `mst`와 `all`이 같은 값을 낸다.
> 그래프 방식의 차이를 값으로 보려면 `avg`(또는 `min`)와 함께 쓸 것. 오버레이의 연결선은 fold와 무관하게 방식대로 그려진다.

## 전송 예시 (오브제 3개, connect=mst · fold=max, list 형식)

```
/scramble/obj   12  0.30  0.40   30.0  0.66  0  -6
/scramble/obj   15  0.62  0.55  -45.0  0.80  0   3
/scramble/obj   24  0.80  0.30    0.0  0.42  0   0
```

## 수신 측 권장 사항
- `id`로 소스를 고르고, `x`/`y`는 패닝·위치, `tilt`는 회전, `tension`은 강도/밀도에 매핑.
- 접촉 순간이 필요하면 수신 측에서 `tension`이 임계값(예: 0.95)을 넘는 순간으로 판단.
- 메시지가 끊기면(오브제 제거) 마지막 값을 몇 프레임 유지한 뒤 페이드아웃할 것 — 서버는 사라진 오브제에 대해 별도 메시지를 보내지 않는다.
