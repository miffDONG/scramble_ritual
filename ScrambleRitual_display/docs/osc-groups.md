# 그룹(세포) OSC 설계 — 초안

전시 서버 → TouchDesigner. 기존 `/scramble/obj`(오브제 1개 = 소리 1개)는 그대로 두고,
**비주얼용 그룹 네트워크**를 별도 포트로 추가한다. 이 문서는 구현 전 개념 설계다.

목표: 오브제가 서로 붙으면 하나의 세포로 **합쳐지고**, 떼면 **분열하고**, 세포끼리 붙으면
다시 합쳐지는 과정을 TD가 끊김 없이 애니메이션할 수 있게 한다.

---

## 1. 그룹의 정의

### 1-1. 결합(bond)과 연결 요소
- 두 오브제 사이에 **결합**이 있으면 같은 그룹이다. 결합은 추이적이다 (A–B, B–C 결합 → A,B,C 한 그룹).
- 그룹 = 결합 그래프의 **연결 요소**(connected component). union-find로 매 프레임 계산.
- **혼자인 오브제는 그룹이 아니다.** 그룹은 항상 2개 이상. (25개 → 최대 12그룹이 되는 이유.)
- 기존 텐션 그래프(MST)와는 **별개의 그래프**다. MST는 "모든 오브제를 반드시 한 나무로 잇는" 상대적 구조라
  멀리 떨어진 두 덩어리도 이어 버린다. 그룹은 **절대 거리 기준**이어야 한다. 거리 행렬(테이블 긴 변 정규화)은 공유한다.

### 1-2. 결합 판정 — 히스테리시스 + 시간 디바운스
쌍 거리 곡선 `pair_tension`(0~1)을 그대로 쓴다. 접촉 측정으로 `d_near`가 잡혀 있으므로 tension 1.0 = 변이 닿은 상태.

| 파라미터 | 기본값 안 | 의미 |
| --- | --- | --- |
| `group_bond_on` | 0.85 | tension이 이 값 **이상**이면 결합 생성 (거의 닿음) |
| `group_bond_off` | 0.60 | 결합 중인 쌍이 이 값 **미만**으로 떨어지면 결합 해제 |
| `group_on_frames` | 3 | on 조건이 연속 N프레임 유지돼야 결합 생성 |
| `group_off_frames` | 6 | off 조건이 연속 N프레임 유지돼야 해제 |

- on/off 두 임계값을 두는 이유: 경계에서 손이 미세하게 떨릴 때 그룹이 매 프레임 생기고 사라지는 플리커 방지.
- 결합 상태는 **쌍(id_a, id_b) 단위로 서버가 기억**한다. 오브제 심볼 ID가 고유하므로 키로 쓸 수 있다.

### 1-3. 마커 순간 유실 보호
reacTIVision은 손이 가리면 마커를 몇 프레임 놓친다. 이때 그룹이 멋대로 분열되면 비주얼이 튄다.
- 사라진 오브제는 `group_grace_sec`(기본 0.5s) 동안 **마지막 위치로 그룹에 남겨 둔다**.
- 유예가 끝나면 정식으로 빠진 것으로 처리(아래 분열/소멸 규칙 적용).
- `/scramble/obj`에는 영향 없음(기존처럼 보이는 것만 전송).

## 2. 그룹 정체성(gid) — 합침·분열의 핵심

연결 요소는 프레임마다 새로 계산되므로 **"어느 그룹이 어느 그룹에서 왔는지"**를 서버가 이어 줘야 한다.
TD가 위치만 보고 추측하게 두면 합침과 "한쪽 소멸 + 다른 쪽 성장"을 구별할 수 없다.

### 2-1. 매칭 규칙 (프레임 t−1 그룹 ↔ 프레임 t 연결 요소)
멤버 집합의 겹침으로 대응시킨다.

| 상황 | 판정 | 규칙 |
| --- | --- | --- |
| **유지** | 요소 1개 ↔ 이전 그룹 1개 | gid 유지. 멤버 증감은 `n` 변화로만 표현 |
| **탄생** | 요소의 멤버가 전부 이전에 무소속 | 새 gid 발급, `event=born` |
| **합침(merge)** | 요소 1개가 이전 그룹 **2개 이상**의 멤버를 포함 | 멤버가 가장 많았던 그룹이 gid를 **상속**(동수면 더 오래된 쪽). 나머지는 `event=merged_into <gid>`로 소멸 |
| **분열(split)** | 이전 그룹 1개의 멤버가 요소 **2개 이상**에 나뉨 | 가장 큰 조각이 gid 상속. 나머지 조각은 새 gid + `parent=<원 gid>`, `event=split_from` |
| **소멸** | 멤버가 1개 이하로 떨어짐 | `event=dissolved`. 남은 1개는 무소속 |

합침과 분열이 한 프레임에 동시에 일어나는 경우(A의 일부가 떨어져 B와 붙음)는
"분열 먼저, 그 다음 합침" 순서로 해석하면 위 규칙만으로 결정된다.

### 2-2. 식별자 두 가지
| 필드 | 성격 | 용도 |
| --- | --- | --- |
| `gid` | 세션 내 **단조 증가, 재사용 안 함** | 혈통(lineage). "이 세포는 7번에서 갈라졌다"를 안전하게 표현 |
| `slot` | **0~11 재사용** 번호. 그룹 탄생 시 비어 있는 가장 작은 번호 | TD 인스턴싱/채널 고정 매핑용. 소멸 시 반납 |

TD는 둘 중 편한 쪽을 쓰면 된다. 혈통 애니메이션은 `gid`+`parent`, 고정 12채널 구성은 `slot`.

### 2-3. 대안: 상태 없는 gid (= 멤버 중 최소 심볼 id)
서버에 상태가 없어 단순하지만, 합침 시 큰 그룹이 작은 그룹의 번호를 넘겨받아 비주얼이 점프할 수 있고,
TD가 merge/split 이벤트를 받을 수 없다. **권장하지 않음.** 다만 디버그용으로 `min_id`를 필드에 같이 실어 두면 유용.

## 3. 그룹끼리의 접근 — 합치기 전 단계

세포막이 늘어나며 서로 끌리는 표현을 위해, **합쳐지기 전** 그룹 사이의 긴장도도 보낸다.
- 그룹 쌍 (A, B)에 대해 `link = pair_tension(가장 가까운 멤버 쌍의 거리)`.
- 무소속 오브제도 "크기 1인 임시 노드"로 이 계산에 넣는다. 그래야 "혼자 있는 오브제가 그룹에 다가오는" 장면도 표현된다.
  (단 `/scramble/group`에는 무소속은 올리지 않는다. 링크 메시지에서만 등장.)
- `link > 0`인 쌍만 전송. 12그룹이면 최대 66쌍이지만 실제로는 가까운 몇 쌍만 나간다.
- `link`가 `group_bond_on`에 도달하면 다음 프레임부터는 합침 이벤트로 넘어가므로 TD는 그 구간에서 융합 연출을 시작할 수 있다.

## 4. 메시지 규약 (그룹 포트)

TD 전용 대상(예 `127.0.0.1:7001`)으로 보낸다. 가변 길이 `members`가 있으므로 **json 형식을 기본**으로 권장.
list 형식이면 `members`는 `n` 뒤에 n개의 int로 펼친다.

### 4-1. `/scramble/group` — 그룹 1개당 1메시지, 매 프레임

| # | 필드 | 타입 | 범위 | 정의 |
| --- | --- | --- | --- | --- |
| 0 | `gid` | int | 1~ | 혈통 식별자 (단조 증가) |
| 1 | `slot` | int | 0~11 | 재사용 채널 번호 |
| 2 | `n` | int | 2~25 | 멤버 수 |
| 3 | `members` | int[] | 심볼 id 목록 | 소속 오브제. 정렬 오름차순 |
| 4 | `x` | float | 0~1 | 멤버 중심(centroid) x, 기준 영역 정규화 |
| 5 | `y` | float | 0~1 | 멤버 중심 y |
| 6 | `radius` | float | 0~1 | 중심에서 가장 먼 멤버까지의 거리 (긴 변 정규화) — 세포 크기 |
| 7 | `cohesion` | float | 0~1 | 그룹 내부 결합들의 평균 tension — 얼마나 단단히 뭉쳤는지 |
| 8 | `age` | float | 초 | 탄생 후 경과 시간 — 막 생긴 세포 연출용 |
| 9 | `parent` | int | 0 또는 gid | 분열로 생긴 경우 원래 gid. 아니면 0 |
| 10 | `event` | string | `none / born / split_from / merged_into / dissolved` | 이 프레임의 상태 변화 |
| 11 | `event_gid` | int | 0 또는 gid | `merged_into`일 때 흡수한 gid, `split_from`일 때 원 gid |

- `merged_into`·`dissolved`는 소멸하는 그룹의 **마지막 메시지**다. UDP 유실 대비로 소멸 메시지를
  `group_event_repeat`(기본 3) 프레임 반복 전송한다 (내용 동일, `n=0`).
- `members`가 있으므로 TD는 각 멤버의 `/scramble/obj` 위치를 끌어와 convex hull·메타볼 등으로 세포 외형을 그릴 수 있다.

### 4-2. `/scramble/group_link` — 그룹 사이 접근, `link > 0`인 쌍만

| # | 필드 | 타입 | 정의 |
| --- | --- | --- | --- |
| 0 | `a` | int | gid (무소속 오브제면 `-심볼id`, 음수로 구별) |
| 1 | `b` | int | gid 또는 `-심볼id` |
| 2 | `link` | float | 가장 가까운 멤버 쌍의 pair_tension |
| 3 | `ax`,`ay`,`bx`,`by` | float | 가장 가까운 두 멤버의 위치 — 막이 늘어나는 지점 |

### 4-3. `/scramble/frame` — 프레임마다 1회, 모든 메시지 뒤
| 필드 | 정의 |
| --- | --- |
| `seq` | 프레임 번호 |
| `n_obj` | 오브제 수 |
| `n_group` | 그룹 수 |
| `gids` | 현재 살아 있는 gid 목록 |

이 목록에 없는 gid는 TD가 바로 정리할 수 있다. 기존 obj 규약의 "끊기면 페이드아웃" 추측을 그룹에서는 없앤다.

### 4-4. 기존 `/scramble/obj`에 1필드 추가 (선택, 하위 호환)
| # | 필드 | 정의 |
| --- | --- | --- |
| 6 | `gid` | 소속 그룹 gid, 무소속이면 0 |

맨 뒤에 붙이므로 기존 수신 패치는 깨지지 않는다. TD가 오브제를 그룹 색으로 바로 칠할 수 있어 조인이 필요 없다.
SuperCollider 쪽은 무시하면 된다.

## 5. 설정값 정리 (런타임 `rt` 키 안)

| 키 | 기본 | 설명 |
| --- | --- | --- |
| `group_enabled` | true | 그룹 네트워크 송신 |
| `group_bond_on` / `group_bond_off` | 0.85 / 0.60 | 결합 생성/해제 tension 임계 |
| `group_on_frames` / `group_off_frames` | 3 / 6 | 디바운스 프레임 수 |
| `group_grace_sec` | 0.5 | 마커 유실 유예 |
| `group_event_repeat` | 3 | 소멸 메시지 반복 횟수 |
| `group_max_slots` | 12 | slot 상한 (초과 시 slot = −1, gid는 정상 발급) |

OSC 대상 목록의 각 행에 `role: obj | group | both`를 추가해 어느 포트가 무엇을 받는지 지정한다.
기본: SuperCollider = obj, TouchDesigner 7000 = obj, TouchDesigner 7001 = group.

## 6. 시나리오 예

| 장면 | 서버 판단 | TD가 받는 것 |
| --- | --- | --- |
| 오브제 5와 9를 맞댐 | 3프레임 후 결합 → 요소 {5,9} 탄생 | `group gid=1 slot=0 n=2 members=[5,9] event=born` |
| 12가 다가옴 | `group_link a=1 b=-12 link 0.3→0.9` | 막이 12 쪽으로 늘어남 |
| 12가 붙음 | 요소 {5,9,12}, 이전 gid 1 유지 | `gid=1 n=3 members=[5,9,12] event=none` |
| 다른 쪽에서 {20,21} 생성 후 접근 | gid 2 탄생, `group_link a=1 b=2` 상승 | 두 세포가 끌림 |
| 두 세포 접촉 | 요소 {5,9,12,20,21}. 멤버 많은 gid 1 상속 | `gid=1 n=5`, 그리고 `gid=2 event=merged_into event_gid=1` ×3프레임 |
| 12와 20을 들어 멀리 둠 | {5,9}, {21} 남음 → 21 혼자라 탈락, {12,20}은 서로 붙어 있으면 새 그룹 | `gid=1 n=2`, `gid=3 parent=1 event=split_from`, 21은 obj에서 gid=0 |
| 손이 9를 잠깐 가림 | 0.5s 유예, 그룹 유지 | 변화 없음 |

## 7. 열어 둔 결정 사항

1. **합침 시 gid 상속 기준**: 멤버 수(제안) vs 나이(더 오래 산 세포). 세포 개념상 "큰 쪽이 먹는다"가 자연스러워 멤버 수를 1순위로 두고 나이를 2순위로 제안.
2. **중첩 그룹 여부**: 그룹 안에 하위 그룹(세포 안의 핵 같은 구조)을 둘지. 현재 제안은 평면 분할 1단계만.
   필요하면 `group_bond_on`보다 낮은 2차 임계(예 0.4)로 "느슨한 군락" 층을 하나 더 계산해 `/scramble/colony`로 보내는 식으로 확장 가능.
3. **분열 조각 중 어느 쪽이 원 gid를 가져가는가**: 큰 조각(제안) vs 중심이 덜 움직인 조각. 큰 조각이 단순하고 예측 가능.
4. **전송 주기**: obj와 같은 프레임 주기로 보낼지, 그룹은 30Hz로 낮출지. 그룹은 변화가 느려 30Hz도 충분하지만 obj와 같은 프레임에 묶는 쪽이 동기화가 쉽다.
